# Session Examples — 2026-10-08

## Keep-Rate: Cross-Tool Headline Mixing

**Scenario:** Keep-rate window shows two tools reporting different kept-lines totals on the same HEAD. _keep_rate_calc.py reports 366,545 kept; _keep_rate_classified.py reports 366,532 (raw_with_lockfiles). Developer picks the lower number for the headline, diffs it against yesterday's calc-tool number, explains the 13-line drop as "blame-map reattribution."

**Problem:** The 13-line gap is cross-tool (classified vs calc tools use different blame-map keys), not a time trend. Yesterday's number came from calc-tool; today's from classified-tool. Diffing across tools hides the real trend: both tools' own series stayed flat.

**Fix:** Pick one calculator for your series (e.g., calc-tool). Record its md5. Never diff classified-tool output against a prior calc-tool number.

## Session-Quality: Self-Referential Error Verification

**Scenario:** Skill line 150 tells you: "If error count seems high, verify trace.log's outcome field — hook substring-matches false positives." You spot a high error rate in trace.log's outcome column. You reread the field to verify the substring classifier didn't false-positive. But trace.log's outcome column IS generated by that substring classifier. You're verifying the classifier's output against itself.

**Fix:** Don't verify via trace.log outcome. Instead, check commit history: count revert/rollback commits, check fix-commit cadence (are fixes landing same-day?), count zero-revert streaks. These are observable in git, not produced by the classifier.

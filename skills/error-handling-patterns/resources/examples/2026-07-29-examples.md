## Worked Example: Validating LLM Semantic Signals
**Scenario:** LLM endpoint returns `finish_reason="tool_calls"` but response contains only plain text, no structured tool calls. Without validation, retry handler triggers assuming incomplete tool execution.

**Correct application:** Before routing to error handler, verify signal against actual output. Check response.tool_calls array length and response structure. Only treat as error if mismatch indicates truncation, not mislabeling.

**Common mistake:** Trust finish_reason label blindly; route to JSON-repair handler unnecessarily, causing retry storms and latency degradation.

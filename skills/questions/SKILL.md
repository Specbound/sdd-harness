# Clarifying Questions

## When to Use
Trigger when a request is missing information that would change the approach or the output — not for tasks where reasonable defaults are obvious.

## How to Ask
1. Identify which unknowns would actually change what you build or how you answer — skip questions whose answer wouldn't change your approach.
2. Ask up to 7 questions, ranked by impact: the question that most changes scope or direction goes first.
3. Batch them in one message — don't trickle questions one at a time across multiple turns.
4. If the user can't or won't answer before you must proceed, state your assumptions explicitly in the response so they're visible and correctable.

## Anti-patterns
- Asking questions whose answer doesn't change the approach (padding, not clarifying).
- Silently guessing on a materially ambiguous request instead of asking or flagging the assumption.
- Asking more than 7 questions — narrow to the highest-impact unknowns instead.
